# 1.1.24 ファントムの敵対引継ぎ

利用者報告：「ファントムがFreecamだと敵対されない」。

## コード上で確認した漏れ

1.1.23の `retargetCurrentEnemies` と `maintainBodyAggro` は `Monster` のみを対象としていた。対象Paper API 26.2.build.129-stableの `Phantom` は `Flying` と `Enemy` を継承し、`Flying` は `Mob` を継承するが `Monster` ではない。このため開始時・継続中ともファントムが対象外になっていた。

## 修正

操作対象の型を `Mob` とし、対象判定を従来の `Monster` または `Phantom` にする。これにより開始前から本人を狙っていたファントムを本体へ引き継ぎ、継続中のスキャン範囲内でも本体を狙わせる。無関係のMobを一律に敵対化しない。

クリエイティブ／スペクテイターの本体は敵対させず、他のターゲットを狙う個体を奪わない。既存の `force-hostile-mob-aggro` と `mob-aggro-radius-blocks` の条件を維持し、スキャン範囲を拡大する変更はしていない。通常のクモなど、既存の条件付き敵対判定も維持する。READMEへの更新情報追加は行わない。

## 検証

Java 25 / Paper API 26.2.build.129-stableでビルド、162件の自動テスト成功。追加した8ケースで、サバイバル・アドベンチャーの本体捕捉と再捕捉、クリエイティブ・スペクテイターの保護、開始時の引継ぎ、他人のターゲット維持、敵対補正無効時の挙動、無関係なMobの除外を確認した。

ローカルのPaper 26.2実装のPhantomのターゲット・攻撃Goalも読取確認したが、実サーバーとクライアントでの旋回・急降下・本体への命中は未検証。実機では同じ個体についてFreecam前後のターゲット・本体への接近と攻撃、クリエイティブ、他プレイヤーを狙っている場合を確認する必要がある。特に検出範囲外の個体まで捕捉する変更ではない。
